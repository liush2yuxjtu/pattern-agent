# 独立规格改版基准测试契约

输入固定为仓库 `patterns/fitted-tshirt/input.dxf` 与 `input-spec.yaml`，基准提交为 `b783898028651c1686e8b69833cd481a9d183200`。不改变两份输入或既有网页。

正向案例使用文件声明的图形单位U，不推定毫米换算。基准生产待确认事项继续保留。测试的是具体自然语言请求由子代理实现代码后，能否交付可复算的新规格、规格补丁、几何补丁与真实DXF。不是已训练通用自然语言编译器或模型间统计评测。

## 四个正向意图

1. `01_sleeve_length`：仅把袖片袖口向下延伸20U。袖山、腋下及以上保持不变，从腋下到内圈袖口逐渐增加长度；袖口、折边、定位点、内部线和文字同步。前后衣身及领条全部保持。
2. `02_body_length`：前后衣身各缩短15U。腰线及以上保持，下摆整体上移15U并保持局部形状，腰至下摆之间平顺过渡；关联的折边、内部线、定位点和文字同步。袖片与领条保持。
3. `03_cuff_width`：袖口展开宽增加10U，左右各放5U。腋下及以上不变，向袖口平顺增加横向放量，袖口宽度、折边、内部线和定位点同步。前后衣身与领条保持。
4. `04_front_neck`：前领中点向下加深10U，领宽、领肩点和肩袖衣身保持。内外两条前领圈相关线与标记一致处理，领条长按基准现状的候选几何长度比联动、宽度保持；该比值只是本测试的明确几何约束，不批准为生产配比。后片与袖片全部保持。

## 案例子代理输出接口

每位实现者只维护自己的 `cases/<case_id>.py`，可在 `work/intent-edit-benchmark/<case_id>/` 写试验。

- 导出 `CASE` 字典：`id`、`title`、`intent`、`affected_pieces`、`preserve_pieces`、`operation`、`parameters`。
- 导出 `edit(model)`，就地修改解析后的中文YAML中的 `完整二维几何`，返回包含实际数值锚点与处理说明的字典。
- 同步所有受影响的线条、定位点和文字位置；排版原点默认保持。保留点列长度、线型、名称、文字内容。
- 主程序随后统一复算接口、尺寸、连接和流程记录，生成新文件；实现者不要自己补猜工艺或生产值。
- 不修改公共读取器、主程序、其他案例或输入。发现无法满足意图时如实返回阻塞/失败，不调低目标。

## 独立审计

审计器不能调用生成器、案例变形函数或共同的复算函数来充当正确性判断。它应独立读取最终YAML和真实DXF，核对几何、23项尺寸和接口、未改区域、意图目标、点位及文字完整性、补丁重放与反向恢复，并探测错误基准/旧值/故障输出。完整生产验收与物理试穿不在本测试通过范围。

负向对照包含未标定情况下“袖子加长2厘米”、含糊的“抬手更舒服”、导致负袖口宽的非法请求。这些案例应不给出伪造成功的DXF。
