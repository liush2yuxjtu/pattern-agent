# FreeSewing Teagan adapter probe

`adapter.mjs` exposes `makeDraft(input)`. It imports the genuine `@freesewing/teagan@4.10.2` and `@freesewing/core@4.10.2`.

```js
const draft = makeDraft({
  mode: 'ENGINE_CONFORMANCE',
  measurements: officialModel,
  options: { fitWaist: true },
  measurementSources: sources,
})
```

Input measurements use FreeSewing millimetres, except `shoulderSlope` in degrees. The included `official-model.json` is generated by the official `@freesewing/models@4.10.2` export `cisFemaleAdult38`. Its name does not mean the canonical garment's size M. It is an engine test model.

Output `panels` contains `front`, `back`, `sleeve-left`, `sleeve-right`. These are four physical panel instances derived from three native templates. They are not the canonical source's four template types, which include a neckband. Body panels mirror the native on-fold seamline around x=0. Sleeve-right mirrors sleeve-left around x=0. No neckband is invented.

Each panel provides `outlineMM`, `pathLabels`, `sourceNativeOps`, `sourceNativeAreaMM2`, `areaMM2`, and `unit`. Its boundary is the native `part.paths.seam`, not `part.paths.sa`. Each named edge includes native cubic commands, semantic endpoint roles, samples, and its millimetre length. Mirrored edge commands retain native coordinates and specify `mirrorX`.

Ten seams refer to two named edges and signed sample direction. Apply direction first, then resample each chain to equal vertex counts before creating particle constraints. Do not zip unequal sample arrays. Shoulder chains run neck-to-shoulder; body sides run underarm-to-hem; armhole chains run shoulder-to-underarm; sleeve underarms run underarm-to-cuff. Sleeve cap edges are reversed by seam direction to match body armholes. The front/back cap division uses native cap arc distance equal to front armhole length. It does not assume the cap's highest point is the shoulder notch.

FreeSewing's native cap fitter stops within 2 mm of total armhole length. This fixture has a 0.007738356729 mm total residual. Individual cap segments retain measured residuals in each seam. They are not silently scaled or declared identical.

The sampler retains exact native move/end points. Native `shiftFractionAlong(1)` returned a 0.16 mm endpoint deviation on the fixture's reversed front armhole, so it is used only for interior samples. No boundary gap is bridged or filled.

## Reproduce

```sh
cd engine-cloth-lab
node --import ./probes/pattern/local-loader.mjs probes/pattern/conformance.mjs
```

The task-local loader resolves only a missing `@freesewing/plugin-transform` to its unmodified official 4.10.2 package in this probe. This handles `@freesewing/core-plugins@4.10.2` importing that package without declaring it as a dependency. If the root project has installed it, normal package resolution takes precedence. The loader is for Node conformance execution. A browser bundler should resolve the normal installed package.

The check runs four actual native drafts. A 20 mm waist increase changes both body outlines and leaves sleeves identical. Increasing `sleeveLength` from 0.3 to 0.4 changes sleeves and leaves the front identical. Increasing `necklineDepth` from 0.25 to 0.3 changes the front and leaves the back identical. It checks nonzero native and adapter areas, agreement with native area within 0.5%, semantic seam direction, canonical source SHA256, and blocking unknown canonical mappings. It writes JSON, parameters, and SVG artifacts next to the script.

## Canonical boundary

Canonical input SHA256 is `88a84e697273724cdb5b4a05116c00cd53b0cb75a4d7e6bdfa5d0b7fd34f181e`. Its coordinates are U and U/mm is uncalibrated. It has no approved human measurements. Its reference size M table does not define approved body measurements or targets. `makeDraft` therefore returns `UNKNOWN` without panel geometry for canonical input unless an explicit approved measurement mapping is supplied. It never fills null values with the official test model.

Teagan has a native short sleeve. Its sleeve hem height is `bicepsRight.x * sleeveLength`; even its normal maximum option does not make a shoulder-to-wrist long sleeve. It also has no native neckband. This conformance draft is not a validated reconstruction, physical mapping, fit result, or production pattern for the canonical fitted long sleeve garment. Its provenance states `goldenEquivalence: NOT_VALIDATED`, and its seam approval is `ENGINE_CONFORMANCE_ONLY`.

## Rest cloth mesh

`mesh.mjs` exposes `makeMesh(draft, { spacingMM = 24, boundarySpacingMM = spacingMM })`. It uses genuine `cdt2d` with constrained boundary edges and interior triangular lattice points. Boundary edge segment counts are unified between paired seam chains before sampling. Each side then uses the same normalized arc parameter t. Named edges, native roles, native curves and signed seam directions are retained.

The output includes global particle `restXY` in millimetres, `triangles`, string `panelOfVertex` IDs, per-panel global particle IDs, boundary constraints, named-edge particle IDs, and per-seam paired boundary particle IDs. `restUVperCorner` contains each triangle's undeformed material coordinates in millimetres. No world placement, particles in metres, body transform, dynamics or solver parameters are supplied.

```js
const mesh = makeMesh(draft, { spacingMM: 24 })
// mesh.seams[i].pairs contains [particleA, particleB].
// mesh.panels[i].triangleRange is [inclusiveStart, exclusiveEnd].
```

Reproduce mesh checks with `node --import ./probes/pattern/local-loader.mjs probes/pattern/mesh-conformance.mjs`. The 24 mm fixture has 1647 particles and 2988 triangles. Each constrained boundary edge is present. No triangle edge properly crosses the panel boundary. All triangle centroids lie inside the panel. Positive triangle areas sum to the sampled boundary polygon's area. The sampled polygon differs from the 3 mm native-curve approximation by 0.096% to 0.104% area. All ten seams have matched t counts and semantic endpoint directions, and use only boundary particles. There are no orphan particles. A 20 mm spacing produces 2320 particles, so resolution is configurable and the default is selected to meet the requested 700 to 2000 particle range for this fixture.

## Independent browser-output oracle

`output_oracle.py` uses NumPy float64 `linalg.svd` on `Ds @ inv(Dm)`. It reads actual browser-exported rest millimetres, converts only rest to metres, and uses the exported frame world positions in metres. It compares every triangle's two singular values and every frame's summary extrema. Its stable control has deformation gradient `diag(1, 1e-9)` and requires the minimum stretch to remain positive at `1e-9`.

The same script parses the actual exported SVG with XML and the actual PDF with PyMuPDF. It compares Golden placement, source line coordinates, closure and all source text positions/content to the canonical YAML. Demo SVG physical dimensions and outline coordinates are compared to the browser JSON. PDF page size, each printed outline vector and the 100 mm calibration line are checked in physical millimetres. `PASS` is limited to these calculations and export invariants; it does not replace the browser artifact's garment verdict.

```sh
python probes/pattern/output_oracle.py \
  --artifact /workspace/shared/engine-cloth-evidence/browser-run-final.json \
  --golden-svg /workspace/shared/engine-cloth-evidence/golden-pattern.svg \
  --demo-svg /workspace/shared/engine-cloth-evidence/demo-pattern.svg \
  --demo-pdf /workspace/shared/engine-cloth-evidence/demo-pattern.pdf
```
