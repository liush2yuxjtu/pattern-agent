# 单 HTML 成品独立复核

本轮结论为 `FAIL_PRODUCT_GATES`。A 架构可保留为实验入口，但当前检查证据还不能支持成品通过。Golden 的实尺度物理验收为 `BLOCKED`。完整引擎样衣没有得到 PASS。

本报告针对 `review/advisor-checks-result.json` 中记录的源码与 HTML 哈希。root 后续修复必须重新验收。报告中的初始缺陷不能直接视为修后仍存在，也不能因修复声明而自动关闭。

## 已复现的缺陷

| ID | 级别 | 问题 | 独立证据 | 修复要求 |
| --- | --- | --- | --- | --- |
| R01 | 高 | Golden SVG 改变原排版。 | `goldenDrawing` 忽略 `排版放置点`。后片相对前片应为 `[-1080.485687,-21.556009]`，实际为 `[506.035341,-11.585112]`。 | 使用源排版坐标，只允许全图统一平移与显示缩放。导出同样保持相对位置。 |
| R02 | 高 | 审计结果可绑定到错误帧。 | 从真实源码提取 `audit()`。等待期间从 F0 改到 F10 后，审计使用 F10 数据，却写入 `auditStep=0`。 | 捕获 artifact 身份、source、job、revision、frame 与网格。提交结果前核对完整身份。审计期间控制并发。 |
| R03 | 中 | 旧探针报告与当前 adapter 不一致。 | `engine-report.json` 的 engine 和 native-seam 源码哈希均不匹配。人体和 WASM 哈希匹配。 | 将旧报告标 STALE。重跑当前小探针，并保存当前哈希。不要靠旧 PASS 放行。 |

复现命令为 `node review/advisor-checks.mjs`。脚本只写 review 目录，不改变产品源码。它的单元环境可复现逻辑错误，不代替真实浏览器验收。

## 源码检查发现的产品问题

| ID | 级别 | 触发条件 | 影响 | 修复要求 |

| R04 | 中 | 导入 demo JSON 缺少某个 settings 字段。 | 缺字段沿用当前控件值。同一文件在不同会话生成不同几何。 | 校验完整输入，或先从固定 schema 默认值建立输入，再应用导入字段。拒绝非法范围，不依赖浏览器静默夹值。 |

R02 还存在跨来源风险。不同来源都会从 REV1 开始，单独比较 revision 不能识别来源。普通 worker 回调已有 `buildJob!==job` 和 revision 防护，这是正确边界。审计回调必须采用同等级防护。

## 已确认的正确行为

- Golden 原始 YAML 哈希与设计阶段核对值一致。原始数据未被 Teagan 覆盖。
- Golden 几何计数为 4 片、126 折线、78 直线、27 文字、1487 折线顶点。此项通过不抵消排版错误。
- 默认 Golden 的 U→mm 保持未知。UI 禁用其物理运行和毫米 PDF。原始 YAML 可单独下载。
- Teagan 明确标为独立短袖示例。未声称它等于 Golden 长袖与领条设计。
- 应力和压力均显示 UNKNOWN。主应变图例使用 `ε=λmax−1`，并注明无单位、非 Pa。
- 独立单元检查确认 identity triangle 得到伸长 1。给定 1.2 与 0.8 的主方向伸长，算法返回 1.2 与 0.8。
- `invalidate` 增加 revision、清空旧帧并设 STALE。旧 revision 的 `addFrame` 被拒绝。
- Timeline 明示回放不增加求解步数。只有最新帧可继续求解。
- JSON 导入不信任旧 PASS、网格或物理帧。demo 输入经过重新生成。
- 求解处于可终止 Worker 中。主线程设置 30 秒 wall limit。停止不会以缓存姿态伪装新结果。
- 人体渲染和原生碰撞均使用同一个 `human.positions` 与 `human.triangles`。当前代码没有引入替代胶囊碰撞。

本轮没有独立重跑浏览器。所读 `initial-3d.jpg` 仅证明截图时 UI 显示 F0、RUNNING、81.0 mm 缝隙、最大伸长 1.726 和未检查碰撞。该截图不能证明任何成衣物理通过。离线打开、Worker 重算、导入往返、停止及截图一致性仍须由候选 HTML 浏览器验收完成。

## 数值验收的范围

已有小探针报告记录两片缝合与固定点测试 PASS，最大缝隙约 0.344 mm。报告同时记录接触半径 3 mm 的人体接触测试 FAIL，5 mm 的对应测试 PASS。由于 adapter 源码已改变，这些是历史范围证据，不是当前候选的验收。

`garment-candidates-report.md` 的完整样衣结果没有 PASS。平面 gentle 候选仅运行 30 步，也就是 0.25 s。该报告记录无人体面穿和自交，但最大缝隙仍约 467.88 mm。此结果只证明短程数值运行，不证明已缝合。

medium 候选到 120 步出现内部顶点、人体面穿和自交。投影候选即使 0 inside 仍有表面穿插。不能把 inside count 为 0、有限坐标、退出码为 0 或一张看似衣服的图作为物理 PASS。

独立碰撞审计保留瞬时检查限制。连续碰撞验收仍为 UNKNOWN。UI 中人体表面 PASS 与点在体内 FAIL 必须在综合判定中合并，不能只显示前者并得出总体安全结论。

## 架构决定

保留 A 作为明确的实验入口。它已经把制版、三角化、真实 WASM 求解、同网格人体和独立几何审计连接起来。实验入口可接受已知物理 FAIL，前提是显示失败、原因和输入身份，不让用户将结果当生产版型。

不要继续把已变形穿模的初始姿态作为默认求解起点，也不要用投影纠正把实际失败藏到初始条件。默认实验可采用已知无交叉的平面摆片、短步数与低刚度原生 seam，但必须显示开缝及装配未完成。更长时间不稳定仍应保留为失败证据。

B 是下一步有价值的离线参考路线。使用固定版本 GarmentCode 和其指定 Warp fork，先对同一组已知单位裁片做装配基准。交换格式应保留 panel ID、二维 rest 坐标、三角形、seam 对应、人体 hash、单位、材料假设、frame 时间和求解器参数。

浏览器可以展示 B 的逐帧结果。该模式必须为 REPLAY。编辑之后，离线结果立即 STALE。只有再次调用实际 Python 求解并取得新 revision 的结果，才能称重算。B 的结果不能直接证明 Rapier 通过。两个引擎都必须交给同一独立几何审计检查。

当前不建议放弃 A 或把 Python 依赖塞进单 HTML。先修复 R01 至 R07，取得诚实可复核的实验入口，再用 B 定位初始装配、缝合安排和碰撞的差异。

## 交付边界

允许交付的名称是“现成引擎实验工作台”。不能称“Golden 衣服仿真已完成”或“成衣物理通过”。最终报告必须分别列出产品门禁、引擎小探针、完整样衣和 Golden 生产条件。任何一个层级的 PASS 都不能向另一个层级继承。
