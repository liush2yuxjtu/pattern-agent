# 试穿评审报告模板 V2.3

首句给出放行意见。紧接着展示原始设计、修前和修后，并写清先看哪里。按问题组织正文。每条摘要显示部位或可见问题、尺码和动作。展开后显示设计判断、对照图、改版与复测。技术证据和完整验收可继续展开。每张图独占一段，保留同视角和短图注。

## 独立 HTML 发布

用户明确要求 HTML 时，按[独立 HTML 六项发布关口](standalone-html.md)组织、验证和放行。本文的读者、证据和复测标准同样适用。

## Markdown 发布

首页用一张带标签的 PNG，按左、中、右排列原始设计图、修前和修后。注明款号、样衣版次、尺码和姿势。用短图注指出要看的部位。把三张独立 PNG 放在「原始设计与上身大图」。使用可比视角、裁切和比例。原始设计图姿势不同时，说明哪些外观判断待同条件复验。缺原始设计图或修前时，标出缺项并展示已有证据。只有二维纸样时，引用其净尺寸、图纸或部位标记作为基准。

交付 Markdown 与独立 PNG。需要移动或转交时，将 Markdown 和图目录按原相对路径打包为 ZIP。解压到空目录后实际打开，确认首页对照、大图和折叠正常。需要单文件 Markdown 时用发布器内嵌，并确认目标阅读器实际显示。

完成[四姿势五类验收](workflows.md#四姿势五类验收)后，从 JSON 清单生成报告。顶层填 `title`、`revision`、`size` 和 `postures`。用 `recommendation` 写定稿意见，用 `findings` 写主要发现，按优先级将复测标准写入 `nextSteps`。如本轮已无复测事项，在 `nextSteps` 中写明结论。可用 `tables` 提供统计表数组。每张表提供 `title`、`headers` 和等宽的 `rows`。在各姿势的 `images` 下填相对路径或带 `path`、`caption` 的对象。需要放多个独立视角时用数组。正式报告填四个不同姿势，下例只展示其中一个。

```json
{
  "name": "自然站立",
  "images": {
    "appearance": "证据/站姿-上身正面.png",
    "strain": "证据/站姿-应变.png",
    "stress": "证据/站姿-应力.png",
    "pressure": "证据/站姿-人体压力.png",
    "folds": "证据/站姿-折角.png"
  }
}
```


每项使用独立 PNG、JPEG 或 WebP。缺项、不可读、解码失败、重复姿势或重复图像会报错。脚本校验文件和结构。发布前仍须目视检查单图、证据匹配和读数，并补齐必要的验收记录。

运行环境需要 Node 和 sharp。省略输出文件名时，在清单旁生成同名 .md。用发布器生成单文件版本时，图片数据随 .md 移动。工程和明细数据仍由交付包提供。

```bash
node scripts/bake-report.mjs /path/to/images.json
node scripts/bake-report.mjs /path/to/images.json /path/to/report.md --sharp /path/to/node_modules/sharp
```

手写的局部复核或当轮报告使用同一格式。装有 markdown-it-py 和 Pillow 的 Python 可将原稿中的本地图片直接写入最终文件，并保留正文、图注及数据链接。

```bash
python scripts/publish_report.py /path/to/draft.md /path/to/report.md
```

只把最终 .md 复制到一个空目录，核对证据清单中每张独立图的内嵌数据能解码，并检查实际预览中的图片加载和关键图显示。在 Codex 侧栏能操作时直接验证侧栏。受限时注明实际验证的阅读器。支持标准 Markdown 的阅读器仍可能限制 `data:` 图片，通用解析通过不足以证明目标阅读器已显示。未通过或仅可定性使用的证据也可展示，在图注保留其局限。

导出脚本生成定稿意见、证据和尾节。交付前按下方模板编排首页对照与逐问题评审。保留完整验收和图片引用。

## 可复制模板

试穿评审首先服务于时装设计师和版师。标题后第一句给出定稿意见。暂缓时说先修什么、保留什么。用部位、轮廓、衣长和厘米描述看款变化。把精确读数和原生记录放在技术证据内。已有问题沿用原编号。每项问题复制一个折叠块，先列阻塞项。保留已确认的试穿条件、面料来源和验收范围。
