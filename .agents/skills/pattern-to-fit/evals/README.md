# 试穿用例与评分

## 首批用例

| 用例 | 独立判据 |
| --- | --- |
| 正常基础 T 恤 | ET、CLO、Style3D 的 2D DXF 和 FreeSewing JS 分开执行。按采集方预先量测的尺寸、裁片和缝边检查实际工程。五视角、五类图审、五类表审、报告格式全部通过。 |
| 缩放或尺码错误 | 换错导入单位或选择同档的另一尺码。使用已知净缝线长度或尺码表定位，修复后独立复量。 |
| 裁片和线型错误 | 独立注入把裁剪线当净缝线、漏镜像件两种故障。用裁片和边标识判定位是否正确。 |
| 缝合错误 | 在相同基线上分别注入漏缝、反向和配错边。检查实际缝合、出现的部位、受影响的图表以及修复复测。 |
| 摆位和穿模 | 在固化基线上只改摆位。用左、右或后视可见的穿模或夹布，以及对应碰撞或几何记录定位。 |
| 缺关键输入 | 去掉无法从其他证据恢复的配缝信息或目标人台量体。验收已完成的工作、结构化补证及 `PENDING` 状态。 |
| 五类证据负对照 | 分别移除每类图和表、投放旧状态数据、重复视角、替换原生读数为代理、在指定区域注入超限证据。预期拒绝放行。盲评记录故障类别和部位。 |
| 报告格式负对照 | 分别测试外链图、漏图、覆盖表缺行、状态错配、缺复测或复测节非末节。预期拒绝报告格式。 |

用例提供实际二维源文件、冻结的 VM 和软件版本、可用人台和物性、正常工程和故障注入方法。评测方预先保存净尺寸、配缝、故障位置、图表限值和目标 verdict。基线、故障、修复均重新捕获相同范围的证据。每个用例写明 CLO3D VM 和 Boat VM 的实际职责。受环境限制的能力单独记录。

## Grader

使用相同模型、工具、VM、输入和时间预算对比 `design-cloth` 与 `pattern-to-fit`。评测员或独立智能体读实际图、CSV 原表、工程回读和求解回执。使用用例方预先设置的判据，逐项复评图与表。重点核对异常位置、取样范围、单位、读数、判据和修复结果。将独立结论写入清单的 `review`，保留复核理由。候选智能体的自评供核对用。真实运行指标与合成负对照单独统计。

### 清单和执行

每个尺码、姿势单独写一份 JSON 清单。以下片段展示字段。实际清单包含五类验证。

```json
{
  "subject": "M/自然站立",
  "state": "实际保存状态的唯一标识",
  "maps": {
    "appearance": {
      "images": {
        "front": {"path": "evidence/front.png", "state": "实际保存状态的唯一标识"},
        "back": {"path": "evidence/back.png", "state": "实际保存状态的唯一标识"},
        "left": {"path": "evidence/left.png", "state": "实际保存状态的唯一标识"},
        "right": {"path": "evidence/right.png", "state": "实际保存状态的唯一标识"},
        "front_left_45": {"path": "evidence/front-left-45.png", "state": "实际保存状态的唯一标识"}
      },
      "table": "evidence/appearance.csv",
      "review": {"visual": "PASS", "tabular": "PASS", "reason": "记录实际读图、读表及判据比对结果"}
    }
  }
}
```

每种诊断类也使用 `images`，并给每张图一个有意义的键名。四种诊断类键名为 `strain`、`stress`、`pressure` 和 `folds`。CSV 至少包含 `state,region,metric,observed,unit,coverage,criterion` 七列和一行实际结果。数值类 `observed` 填有限数字。外观可用结构化文字和定量长度。缺证时保留对应类条目和已审查结果。每个路径相对于清单所在目录。

在 Python 3.10+ 环境安装 `markdown-it-py` 和 `Pillow`，再使用复制的发布脚本和评分器。

```bash
python scripts/publish_report.py /path/to/draft.md /path/to/report.md
python evals/grade-fit.py /path/to/evidence.json /path/to/report.md
```

脚本读实际 CSV、报告和图像字节。逐项核验图与表、比对状态标识和图像内容、校验 Markdown 版式及五项覆盖表。原生来源、相机实际角度、读数是否过线和外观是否合格，由独立复核员按工程、运行回执、原图和原表判定。脚本检查复核结论并汇总。

- 试穿证据关口须五类图审和表审全部 `PASS`，任何可信失败保留 `FAIL`，其余缺证为 `PENDING`。
- 报告格式独立判定。Markdown 包含规定章节、真实内嵌图、对应覆盖表、读数摘要表和原表链接。分诊与下一步复测在正文末节。每个证据单元均用上面的评分命令检查。
- 评测员另判报告的判断质量。开头要有明确的放行决定、第一优先部位或下一步、可追溯的图表依据，以及会改变决定的条件。完成验收且无待办时，明确放行范围和主要依据。仅复述图表、用未设限值的读数判超限、把待证原因写成确认结果，均判该项失败。
- 退出码 `0` 表示全过，`1` 表示验收失败或报告格式失败，`2` 表示格式通过但仍待补证。
- 看试穿实际状态和用例成绩两项。故障用例准确定位并给出预期 `FAIL`，该用例可通过。缺输入时，预期的 `PENDING` 也可通过。

从零起版的历史用例见原 `design-cloth` 的 `evals/README.md`。
