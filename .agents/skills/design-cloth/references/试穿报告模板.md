# 〔款式〕试穿报告

版式范本为 [M 码女式紧身针织 T 恤从原始 DXF 重建的四姿势试穿报告](https://chatgpt.com/space/page_c0a18719f4888191ba82428b17fd6a73)。保留先看问题、再看整体和局部、最后安排复测的顺序。按当前服装的范围选择姿势、部位和指标。套用时移除填写说明及范本数据。

正式报告默认交付 Markdown（.md）、同目录的独立证据图和发布清单。以大图和短图注为主，用多级标题区分姿势、部位和证据。每张图只显示一个姿势、视角或证据，使用独立原图或独立渲染。用独占一段的 `![姿势 · 视角或指标](证据/对应图.png)` 插图，下方放短图注。正文没放的证据图移到「补充图像」，按姿势或指标展开插图。索引表用图号指向正文，原始数据和工程保留普通链接。设计线稿、上身图及修前修后用相邻的独立图。开头用「先看哪里」分点写主要发现和当前状态。所有统计和验收表集中放在末尾的「结论与复测标准」一节之前，用图号和表号互相对应。

当轮复核报告可精简为本轮结论与范围、独立证据图、[结论与复测标准](#七结论与复测标准)。文件名带款式、尺码和复核范围，例如「牛仔裤-M-效果图外观复核报告.md」。开头记录工程版次、尺码、已测姿势及判定。待补的证据和适用的后续验收写在复测标准中。整衣关口尚未通过时，明确写「本轮交付当轮复核报告，四姿势五类验收完成并通过后才发布正式定稿」。复核报告直接写成 Markdown，正式报告按下节发布。

## Markdown 发布

完成[四姿势五类验收](workflows.md#四姿势五类验收)后，从 JSON 清单生成报告。顶层填 `title`、`revision`、`size` 和 `postures`。把验收结论写入 `findings`，按优先级将复测标准写入 `nextSteps`。如本轮已无复测事项，在 `nextSteps` 中写明结论。可用 `tables` 提供统计表数组。每张表提供 `title`、`headers` 和等宽的 `rows`。在各姿势的 `images` 下填相对路径或带 `path`、`caption` 的对象。需要放多个独立视角时用数组。正式报告填四个不同姿势，下例只展示其中一个。

```json
{
  "name": "自然站立",
  "images": {
    "appearance": "证据/站姿-上身正面.png",
    "strain": "证据/站姿-应变.png",
    "stress": "证据/站姿-应力.png",
    "pressure": "证据/站姿-人体压力.png",
    "folds": "证据/站姿-折角.png"
  }
}
```


每项使用独立 PNG、JPEG 或 WebP。缺项、不可读、解码失败、重复姿势或重复图像会报错。脚本校验文件和结构。发布前仍须目视检查单图、证据匹配和读数，并补齐必要的验收记录。

运行环境需要 Node 和 sharp。省略输出文件名时，在清单旁生成同名 .md。报表与原始图片一同移动时保留相对目录结构。

```bash
node scripts/bake-report.mjs /path/to/images.json
node scripts/bake-report.mjs /path/to/images.json /path/to/report.md --sharp /path/to/node_modules/sharp
```

在实际交付位置预览 .md，逐一核对清单图片在正文或补充图像中加载、图注对应、移动后的相对路径有效。展示已取证和判定是两件事：未通过、定性或映射待核的证据照样可展示，并在图注注明局限。用户明确要求独立的离线 HTML 时，将输出路径指定为 .html，随后独立打开检查内嵌图。

## 写给不同背景的读者

- 正文和图注先点出服装部位，再说看到的现象、改动和复测结果。分清已确认的发现和仍待核实的原因。让没有服装背景的工程师读完开头和图注，就能指出问题位置、理解验收状态，并知道下一步要核对什么。
- 保留版师和设计师做决定要用的部位名、尺寸、单位、缝长差、改动量和关键读数。必要的专业术语首次出现时用一句话说明它在这件衣服上指什么，例如「后育克是后腰下方的拼接片」。解释读数时说清它反映什么和采用的判断依据。
- 将软件接口名、网格细节、计算公式和详细统计放在结论前的「集中统计与验收」或链接到相应证据。正文保留会影响判断的条件、关键读数、证据局限和不确定性。交付前检查工程师能否看懂现象与下一步，以及版师和服装设计师能否按标注找到部位、尺寸与判断依据。

## 一、先看哪里

**本轮结论**　〔用带简短小标题的项目符号写明最重要的发现、支撑数字、实际状态及本轮范围。首条先说最值得处理的部位。〕

〔大幅嵌入最能说明问题的图，直接标出优先看的部位。图注简写尺码、姿势、视角、版本和来源。〕

## 二、看整体上身

〔按姿势逐张插入独立的正背面图，必要时加侧面。做设计对照时，把同视角、同闭合状态的独立上身图和线稿相邻放置。用一两句指出姿势变化时最明显的差别。〕

## 三、按部位看图

### 〔部位与问题〕

〔先放大的定位图或局部图，标出实际取样边界。跨姿势或修前修后用相邻的独立图，保持部位、视角、闭合状态、裁切尺度和色标可比。局部评审也须用能直接支撑结论的图。〕

**取样范围**　〔用一句话写清区域边界、指标、单位及统计口径，例如按面积加权的超阈值比例。〕

〔图注给出对应表号，便于查阅集中统计。〕

**结论**　〔一句话说明图和数字共同支持什么，以及为什么这个部位值得先查。视觉检查项写可见结论；数值项取同版对应数据。〕

范本示例：在应变图上标出两侧前腋点周围半径 55 毫米。自然垂臂时，前腋有 47.5% 的面积伸长超过 10%，整个前片为 3.3%；侧平举时分别为 100% 和 39.7%。局部与整片的对照说明应优先复核前腋。10% 是该报告的比较阈值，正式验收采用约定条件。

## 四、详细分析与复测记录

〔解释各重点部位的可见现象、证据支持的判断和待排查原因。说明版本、尺码、姿势、人台与量体来源、实际用料和物性来源、闭合与缝合状态、主机及模拟时长或步数。〕

〔简述本轮选做的快速排查及结果，附对应候选版和证据路径。出现人台尺寸差异时，记录设计目标、实际读数、差值及调整后复测。记录其他输入偏差及其复查结果。〕

〔有修复时，用配对图和数值交代改动部位、改动量、同条件复测结果及是否复发或引入新问题。保留失败或退步的尝试，并链接匹配的工程或网格。〕

## 五、补充图像

〔按尺码、姿势、版本或证据类别直接嵌入正文未展示的必要图片。每张图独占一段，下方用短图注写明部位、视角与来源。用图号对应同轮数据、工程或网格。〕

## 六、集中统计与验收

### 表 1 分部位或姿势统计

| 姿势或版本 | 局部统计 | 比较基准 |
| --- | --- | --- |
| 〔姿势或版本〕 | 〔统计值、单位〕 | 〔整片、另一姿势、修前值或约定门槛〕 |

〔按尺码、姿势、部位和检查项汇总所有已取得的数值结果；逐点或逐面明细链接原始表。记录单位、样本数或面积覆盖、取样或加权方法、适用的阈值与基准。数据支持时给出中位数、高分位、峰值及位置。原生应力和压力引用原生测点或导出。〕

### 表 2 验收覆盖

〔用一张短表交代本轮适用的验收覆盖，包括应变、应力、上身与线稿对照、接触压力和折角。完整验收缺必要证据时，按工作流程继续补采图像、取得数值或对照结果、完成视觉评审。可行路径用尽仍受阻时，写明实际障碍、补采尝试和恢复条件。〕

## 七、结论与复测标准

1. **先做〔最高优先动作〕。** 〔写明部位、依据、由谁执行、使用的工具和这一轮要改或补采的一项。指定复测姿势、应保持相同的条件、重复统计口径和通过条件，并检查是否引入新问题。〕
2. **再做〔其余必要动作〕。** 〔按优先级写需要的测试和标准。已完成验收时，仅列仍有实际后续的事项。〕

将每个优先复测动作写到可以判断结果的程度。已约定限值时，说明在哪个姿势、哪个部位、用什么口径判断达标。没有限值时，给出与现象直接对应的可观察判据，并注明它是建议采用的局部复测标准。比如对局部外观拉纹，若设计要求该处平顺，保持同一视角、姿势和闭合，观察原拉纹是否仍可见、附近是否出现新增牵扯或穿插。若拉纹可能是设计效果或自然褶皱，先用设计参考或版师确认厘清保留条件。仅能确认是否复现时，将诊断完成条件和修复通过条件分别写明。

〔若下一步需要用户补证或作决定，引用相应图表，写明推荐动作和理由。有可选方案时列出各自影响。按[疑难交接](workflows.md#定稿与疑难交接)在交付当轮报告前实际调用 `AskUserQuestion` 或当前环境的结构化提问工具发出具体问题。报告里的这段说明仅记录交接事项。收到答复后继续验收。〕

范本示例：先复核袖子装入的位置、角度和缝合。若证据指向局部活动量，再单独试一次腋下调整。用同一人台、面料和取样区复测自然垂臂与侧平举，看前腋超阈值面积是否降低、下摆是否上移，以及有无新增穿插。未经约定的量值作为比较或建议门槛。
