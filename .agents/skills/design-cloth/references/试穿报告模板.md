# 〔款式〕试穿报告

首句给出定稿意见。按问题组织正文。每条摘要显示部位或可见问题、尺码和动作。展开后显示设计判断、对照图、改版与复测。技术证据和完整验收可继续展开。每张图独占一段，保留同视角和短图注。

## Markdown 发布

完成[四姿势五类验收](workflows.md#四姿势五类验收)后，从 JSON 清单生成报告。顶层填 `title`、`revision`、`size` 和 `postures`。用 `recommendation` 写定稿意见，用 `findings` 写主要发现，按优先级将复测标准写入 `nextSteps`。如本轮已无复测事项，在 `nextSteps` 中写明结论。可用 `tables` 提供统计表数组。每张表提供 `title`、`headers` 和等宽的 `rows`。在各姿势的 `images` 下填相对路径或带 `path`、`caption` 的对象。需要放多个独立视角时用数组。正式报告填四个不同姿势，下例只展示其中一个。

```json
{
  "name": "自然站立",
  "images": {
    "appearance": "证据/站姿-上身正面.png",
    "strain": "证据/站姿-应变.png",
    "stress": "证据/站姿-应力.png",
    "pressure": "证据/站姿-人体压力.png",
    "folds": "证据/站姿-折角.png"
  }
}
```


每项使用独立 PNG、JPEG 或 WebP。缺项、不可读、解码失败、重复姿势或重复图像会报错。脚本校验文件和结构。发布前仍须目视检查单图、证据匹配和读数，并补齐必要的验收记录。

运行环境需要 Node 和 sharp。省略输出文件名时，在清单旁生成同名 .md。报表与原始图片一同移动时保留相对目录结构。

```bash
node scripts/bake-report.mjs /path/to/images.json
node scripts/bake-report.mjs /path/to/images.json /path/to/report.md --sharp /path/to/node_modules/sharp
```

在实际交付位置预览 .md，逐一核对清单图片在正文或补充图像中加载、图注对应、移动后的相对路径有效。未通过、定性或映射待核的证据可在图注注明局限。用户明确要求独立的离线 HTML 时，将输出路径指定为 .html，随后独立打开检查内嵌图。两种格式交付前都用 `python3 evals/check-report-follow-up.py /path/to/report.md`（或 `.html`）核对尾节，按本轮实际证据检查编号和待办。检查器的准备和用法见[报告评测](../evals/README.md#试穿与复验报告)。

导出脚本生成定稿意见、证据和尾节。交付前按下方模板编排逐问题评审，将支撑图和技术记录放到对应问题下，并保留完整验收与图片引用。

## 可复制模板

试穿评审首先服务于时装设计师和版师。标题后第一句给出定稿意见。暂缓时说先修什么、保留什么。用部位、轮廓、衣长和厘米描述看款变化。把精确读数和原生记录放在技术证据内。已有问题沿用原编号。每项问题复制一个折叠块，先列阻塞项。保留已确认的试穿条件、面料来源和验收范围。

