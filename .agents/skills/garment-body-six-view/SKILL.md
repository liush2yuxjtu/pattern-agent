# 服装六视图与参数化人体拟合

把原始商品图、六张独立图、真实解剖网格和验证证据串成可复算的交付。
复用已有图片、授权、尺寸偏好和模型；只执行本轮要求的分支，不默认重新付费生成。
生成、拟合、导出或核验请求需要实际运行文件；计划、命令示例和自报数字不算完成。
先检查资源与可执行入口，完成一个端到端结果，再扩展。缺少工具时报告受阻部分，继续独立工作。

仅从纸样 JSON/GarmentCodeData 做服装网格和下垂时，使用 garmentcode-preview；
照片人体拟合才组合两者。视觉吻合或干净裸模不代表物理试衣通过。

## 1. 获取原图与确定证据等级

先实际查看原图，保存来源 URL/附件 ID、像素尺寸和 SHA-256；链接、标题和重绘图不能替代原图。
下载失败可换官方页面或浏览器，仍不可获取才请求附件。核对商品领口、袖长、纹理、印花、
扣件、饰品和版型，记录可用视角、是否同一人、姿态、相机、尺度及输出要求。
弯臂、头发和裁切会遮住袖口或领口；先用官网说明及同款其他照片交叉核对，再冻结商品细节表。
官方模特身高/穿着尺码与用户采用的人体先验分开保存，不能用尺码代替围度。

在 run.json 选择模式：
- `observed_fit`：同一人的原始多视角约束可见外观与体形。
- `prior_avatar`：单张原图，其余由 AI 补出；尺寸是与参考一致的假设人体。
- `relative_only`：无可靠尺度且不采用身高假设，只给比例或归一化尺寸。

M 码不能推出身高或胸腰臀。获准假设时明确数值与先验来源；身高只能解决尺度，
不能消除遮挡、松量和透视歧义。没有尺度不将像素写成厘米。

## 2. 建目录与建立真实裸模

使用当前可写项目目录，分开 reference/、images/、model/、evidence/，并保存 viewer.html、
measurements.json/CSV、report.md、run.json。记录软件版本、资源/输入哈希、模型版本、
相机、坐标、单位、参数边界及生成工具实际设置；不编造工具结果。

Pattern Agent 默认复用 [Human Studio 解剖模型](https://liush2yuxjtu.github.io/pattern-agent/human-studio/)。
先读 [Human Studio 工作流与数据合同](references/human-studio.md)，按实际版本使用 MakeHuman
网格、形变和蒙皮；其他许可合适的解剖模型也可。椭圆、胶囊等代理只作标记清楚的数值控制
或用户接受的临时替代。不虚称使用 SMPL、模型权重或物理引擎。

体形、姿态、相机、服装松量分组。至少支持身高、胸腰臀、肩部、前侧背与旋转；
尺寸实际改变顶点，骨骼姿态实际驱动蒙皮。检查有限顶点、正尺度、合理比例、连续形变、
网格边界及非流形边；关节变形不等于碰撞、组织或布料仿真。

用户要求保持原图动作时，以该动作作为固定目标，不重置为 A-pose。用同一个参数化人体联合
优化可辨识的厘米尺寸、骨骼位置/长度、关节角度和相机；可以分块求解，但最终所有视图共享
同一份 dimensions、morphWeights、完整 poseDegrees 和真实 posed 网格，只改变观察相机。
不能给正侧背各拟合一套姿势冒充统一匹配。单独调尺寸时保留当前关节角度；骨骼世界位置会随
体形改变，不要把“同姿态”误写成所有关节世界坐标不变。实际骨头段长与表面带尺长度分开报告。

Human Studio 为 X 左右、Y 向上、Z 前后；OBJ cm，GLB 世界坐标 m。显式记录跨软件
轴/尺度变换，防止导入器转换后再重复缩放。尺寸以 neutral 网格为准，弯膝后包围盒高度
不是站立身高；肩峰距离、肩关节间距和外轮廓肩宽分开，带尺路径、截面围度和直线长度分开。

保存 dimensions 目标、measuredNeutral 实测、maximumTargetErrorCm、morphWeights、完整
poseDegrees、version 与 asset 指纹。独立重建匹配资源的中性网格复量，不能只读自报字段。
超出形变范围报告最近结果与残差；四肢截面优先垂直肢体轴线，其他定义明确标注。

执行导出、相机、姿态/深度或拟合时，按 [几何证据合同](references/geometry-evidence.md)
保存可复核产物；其中说明 neutral/posed、OBJ/GLB 实际边界、紧凑顶点索引重映射与深度有效性。

## 3. 六张独立图与几何图

以原商品照约束外观，以同一版本裸模渲染约束体形/姿态。先调尺寸和姿态，再冻结相机；
Human Studio 尺寸/预设会重取景，状态 JSON 不含相机，严格比较需独立保存投影与视图矩阵。
提示包含原图细节、模型版本/参数、视角、姿态、相机、画幅、分辨率与推断项。
保持人物、服装、背景、光照和身体边距一致；记录每张实际原生像素尺寸。

交付独立的 front.png（正面全身、手臂稍离躯干）、side.png（90°侧面全身）、back.png
（背面全身、未见结构标推断）、closeup.png（穿着纹理与关键接缝）、pose.png（对应选定正面
的点线）、depth.png（同一相机/姿态的相对深度）。不把拼图裁块或放大称为独立高清生成。
工具支持独立批量就批量，否则分次调用。
已有指定动作时，正侧背沿用这个动作；手臂稍离躯干的默认姿势仅用于没有指定动作的任务。
生成后先对照原图与细节表逐项检查商品；错误袖长、领型或饰品应修正并保留失败轮次。
商品一致性、生成视图几何吻合与真人尺寸准确性分别评价，任何一项不能替代另两项。

姿态来自实际执行的检测器或真实骨架投影；深度来自实际 Z-buffer/估计器，记录模型版本与
深度语义。几何输出保留像素坐标、可见性、原始深度、有效掩膜、相机与网格/姿态标识，
检查有效像素非空且有限。单目相对深度不代表厘米深度。
用户要求生成风格或缺少推理工具时可交付 `illustrative` 示意图，但不作测量数据。
自由生成照片与几何图没有天然逐像素配准；不匹配时重新对齐或明确限制。
用户选用 Image Gen 姿态图指导拟合时，先把标注配准回未改动的原图，保存变换、内点误差和
原始坐标。逐点核对解剖语义：领口不是颈关节，腰带不是髋关节；示意点用作带权引导，
不能升级为检测真值。被遮挡的关节与手掌朝向仍需在真实网格侧视图中检查。

## 4. 冻结参考并实际拟合

切换新的商品、姿态或裁切时，先读 [跨商品拟合流程](references/cross-product-fitting.md)。
已有商品的求解代码只作实现参考；相机、像素标注、表面代理和动作先验都应从本次输入重新建立。

分别报告原始照片拟合和生成视图内部一致性。用生成器输入裸模拟合其生成图是闭环，
不能证明真实人体尺寸；生成背面留出也不变成独立真人验证。单张真图的侧背仍是先验。
二维关节点对齐后再看真实正侧渲染中的手掌朝向、前后遮挡和明显穿身；点误差小不等于三维姿态合理。
提衣、捏合等动作还要检查腕部旋转、拇指与手指屈曲；手腕落点相同而双掌仰翻张开仍是动作失败。
围绕同一目标动作实际执行尺寸/骨骼、姿态与相机的联合或交替优化，保留各参数块的初始与最终值。
对每张渲染记录同一状态/网格哈希与独立相机；重新投影复算，拒绝按视图换姿态、换人体或只改标签。
缺少可复用联合求解器时先建立可运行入口并用真实模型执行，不以计划或一组失败候选替代拟合工作。

用 OpenCV GrabCut、分割模型等建立并展示参考掩膜，检查阴影、背景与肢体间空隙。
低分辨率分割记录实际分辨率，不暗示原图边界精度。先对齐相机/尺度，再冻结参考哈希、
评价区域、图像分辨率与相机。初始和最终投影来自实际网格；优化相机时单列其贡献，另做冻结相机对比。

保存初始参数与指标，用 SciPy/三维软件实际优化可辨识的体形、姿态和轮廓，保留合理比例、
正尺度、连续形变与胸腰约束。不压扁躯干追逐发髻，不任意减固定松量冒充裸身围度。
不透明衣物可作裸模的包含上界；用合理先验约束可辨识的尺寸，分别报告越界、轮廓和关节点，
避免把缩小裸模后包含性变好说成全轮廓吻合或真人围度准确。
每轮保留参数、损失、约束、各视角进退；连续两轮改进很小、违反约束或最弱视角不再改善时停止，
保留最佳可解释版本。原始多视角尽量留出一视角。重新生成参考另开迭代，保留旧图。
即使编辑提示要求人物位置不变，也要重新检查图像、关键点、掩膜和相机；将最终指标绑定到
这轮参考图的 SHA-256，构建查看页时拒绝不同轮次图像与旧指标混用。

初始/最终网格在相同最终评价分辨率重渲染，计算 IoU、Dice、对称轮廓距离均值/P95（像素）；
展示绿=重合、粉=参考独有、青=模型独有的叠加，保留前侧背和透视真实网格快照。
说明头发、衣物、手部差异；IoU 不是人体尺寸准确率，像素误差不是厘米误差。
从最终保存的资源/网格独立复量尺寸，绑定同一最终版本，而不是复述求解目标。

评价不能只追踪脸和手腕：这些点对齐时，躯干与骨盆仍可能严重偏移。优化前冻结肩、双臂、
躯干及腰臀区域，分别检查越界比例、轮廓距离 P95、中心线和关节点残差。关键区域失败应
否决整体视觉匹配，不用全图均值或功能测试通过率稀释；衣物松量与头发区域另列限制。
评分器从实际 OBJ 与相机独立重投影，并用故意移偏骨盆、按视图换姿势和伪造指标的反例
确认能检出错误。功能可用、二维吻合、三维合理及真人尺寸准确性分别给结论。

## 5. 同步查看器与状态

查看器载入最终网格，默认控件、标签、相机、参数与导出保持同版本；尺寸 cm，角度 degrees。
按真实 UI 类型、范围、步长规范化同一份状态后再建控件、标签和几何，避免浏览器 range
自行取整但模型仍用旧值。保存状态带版本/资源指纹；导入兼容性检查并保留形变和完整姿态。
setPose 替换整张表，局部编辑先合并；细节与当前 0.1 步长见 Human Studio 参考。

实际检查几何/画面变化、前侧背相机、保存/重载/导入、越界/非法类型/非步长缓存、旧缓存隔离、
窄屏无横向溢出与运行错误。改身高后复量围度，防止全局缩放使标签失真；围绕截面中心缩放
以免移动中心线。生成按钮提交当前参数和原图引用；无生成后端时明确说明。

## 6. 尺寸来源与交付

人体尺寸的主要输出来自最终保存的真实中性裸模网格，不能把 M 码先验、dimensions 控制目标
或缓存 measuredNeutral 直接复制成结果。先读 [模型实测导出合同](references/model-measurements.md)，
实际运行 `scripts/export_body_measurements.py`，从 neutral.obj 顶点及资源定义的带尺/标志点复量，
绑定最终 state、asset、neutral/posed 网格指纹。姿态只影响摆姿，站立身高和围度从同版本 neutral 测量。

主要 JSON/CSV 使用 `measured_values_cm` 和逐项 `value_cm`，`basis: mesh_measurement`；
输入先验、拟合后的控制目标与实测值分列，目标仅存 `target_dimensions_cm`，报告残差和定义。
查看器/评阅页默认展示与下载模型实测结果，历史先验记录明确标为历史。编辑尺寸后重新测量，
单独改姿态不能改变中性尺寸；不能为了导出而重新拟合目标或修改已评分的历史网格。

每项给名称、值或 null、单位、定义、截面/标志点、来源与限制。围度带尺路径不是截面围长，
标志点直线长不是骨头段长；无对应可靠几何定义的胸点距、下胸围、肩斜、前后腰节长和裆弧保留 null。
`mesh_checked` 说明模型测过，`parameter_basis` 另记形体的先验/拟合来源；模型实测不会自动成为
照片真人实测。无可靠尺度使用归一化单位，不编造厘米或无统计依据的置信区间。

按本轮范围交付六图、真实网格/参数/可调查看器、快照、叠加、初始/最终指标、CSV/JSON 与说明；
直接链接可打开证据，区分已运行验证、目视检查与未运行项，指出最弱视角、先验尺寸及还需的真实证据。
默认 eval.html 保持 Anthropic 官方查看器格式：图库放在各案例的 Output 内，保留 Prompt、
Outputs / Benchmark、Formal Grades、Previous Output、案例导航与官方反馈流程。原图、实际姿态
引导、真实相机渲染和初始/最终叠加按同一画幅展示；可选交互详情页提供透明度、
细轮廓与放大，避免大块不透明颜色遮住偏差。侧背图用于查看同一状态的三维合理性。
历史成绩保留为历史，并显示新评分标准下的失败区域；文件齐全不等于视觉匹配通过。

计算与测量前读 [工具与证据实现](references/tools-and-evidence.md)：
`scripts/verify_masks.py` 计算 OpenCV 指标/叠加；`measure_mesh.py` 测真实连通截面；
`inspect_human_state.py` 有匹配 human.json 时独立重建中性网格，无资源时仅结构检查；
`export_body_measurements.py` 直接复量保存的裸模 OBJ，导出主要人体尺寸 JSON/CSV。
脚本不替代原图、拟合、生成服务或解剖判断；完整浏览器与导出验证入口见 Human Studio 参考。

修改本技能或评分器时，按 [反馈与功能评测迭代](references/evaluation-workflow.md) 执行：
先保留用户看到的旧结果，再用实际输出检验断言与漏检反例，展示证据并收集绑定模型版本的
人工反馈。功能通过率不能代替动作验收；单个案例调参也不能写成通用技能或触发率提升。
