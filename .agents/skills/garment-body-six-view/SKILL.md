# 服装六视图与参数化人体拟合

把原始商品图、生成视图、三维人体和验证证据串成可复查的流程。
优先完成已授权工作，复用对话里的商品、图片、尺寸偏好和模型。
不反复询问已确认的信息；只询问阻碍执行的关键缺口。
用户仅要求尺寸、继续拟合或修复查看器时，复用已有图片，不默认重新付费生成六图。
交付范围服从本轮请求，已有授权和约束跨轮保留。

## 邻近流程的边界

仅从纸样 JSON 或 GarmentCodeData 生成服装网格、下垂和预览时，使用仓库的 garmentcode-preview 工作流。
只有同时要求照片人体拟合时才组合两者；本技能不会把视觉拟合或干净的裸模升级为物理试衣通过。
纯商品图修图、普通选码和无照片的量体表处理也不需要完整六图/人体流程。

## 1. 确定输入和证据等级

先查看原图，再写生成提示。保存原始文件、来源 URL 或附件 ID、像素尺寸和 SHA-256。
链接、商品标题和模型记忆不能替代实际图片。下载失败时可换用可用的官方页面或浏览工具；
仍不可获取时，明确缺口并请求附件。不要把重绘图冒充原始商品图。

记录：商品外观、可用视角、是否同一模特、姿态、相机、已知尺度、用户指定体形及输出要求。
核对领口、袖长、织纹、印花、扣件、饰品、版型；不要凭类别名称补细节。

选择模式，并写入运行记录：
- `observed_fit`：有同一人的原始多视角，可用它们约束外观与体形。
- `prior_avatar`：仅单张原图，其余视角由 AI 补出；输出与参考一致的假设人体参数。
- `relative_only`：没有可靠尺度且不采用身高假设；输出比例或归一化尺寸。

M 码不是统一人体尺寸，也不能推出身高或胸腰臀。用户允许主动假设时可以选择演示体形，
但将具体数值和依据明确标为先验。没有尺度时，不把像素直接写成厘米。
身高假设只解决尺度，不能解决衣服遮挡、松量、透视和体形歧义。

## 2. 建立可复现的运行目录

使用当前环境的可写项目目录，不写死对话路径、品牌、SKU 或先前尺寸。
将中间文件与交付文件分开。至少保留：

- `reference/`：原始商品与模特图及来源记录。
- `images/`：六张独立图像。
- `model/`：OBJ、GLB 或其他真实三维网格，参数和版本。
- `viewer.html`：可调节、可旋转的裸模查看器。
- `evidence/`：分割掩膜、投影掩膜、叠加图、三维快照和指标。
- `measurements.json`、`measurements.csv`、`report.md`、`run.json`。

记录软件版本、相机锚点、单位、参数边界、参考文件哈希及生成工具的实际设置。
先检查工具可用性；缺少图像生成、三维计算或浏览器验证能力时，明确受阻部分，
继续完成可独立执行的工作。不要编造工具执行结果。

## 3. 建立真实可调节的裸模

先建可渲染的三维网格，再做人体测量与拟合；不要用另一张生成图片替代三维软件快照。
在 Pattern Agent 中，默认使用 [Human Studio](https://liush2yuxjtu.github.io/pattern-agent/human-studio/) 的解剖人体、厘米尺寸与骨骼姿态控制。
先阅读 [Human Studio 工作流和数据合同](references/human-studio.md)，复用版本化 MakeHuman 网格、形变目标和蒙皮权重。
当前实现提供 12 个厘米尺寸、163 根骨骼、姿态预设和关节编辑；体形与姿态分别保存。
用户需要可用人体时，不用椭圆截面、胶囊或圆柱拼成的测试模型代替。简化代理只用于明确标注的数值控制，或用户明确接受的临时替代。
其他任务可使用 Python + NumPy/SciPy/VTK、Blender，或已有且许可允许的 SMPL/SMPL-X 模型；按实际使用的资源声明能力。
不要声称调用了未实际使用的模型、模型权重或物理引擎。

记录并保留模型的真实坐标约定。Human Studio 使用厘米、X 左右、Y 向上、Z 前后；不要套用 Z-up 截面或只改单位标签。
OBJ 以厘米导出，GLB 遵循 glTF 以米导出。跨软件转换时显式记录缩放、旋转及是否已由导入器完成，防止重复转换。
把体形、姿态、相机和服装松量分为不同参数组，避免用扭曲人体掩盖相机错误。
至少支持身高、胸、腰、臀和肩部调节，以及前、侧、背视角和旋转。
肩关节间距与人体外轮廓肩宽分别命名；周长与直线宽度分别命名。

检查有限顶点、正尺度、合理比例、变形连续性、网格边界和非流形边。
从实际网格的固定带尺路径或定义截面计算尺寸，不用输入标签代替测量结果；两种方法分别命名，不能混为同一个围度定义。
Human Studio 的尺寸以中性姿态网格为基准；弯膝后的包围盒高度不是站立身高。肩宽是双侧肩峰标志点距离，不是肩关节间距或衣服外轮廓宽度。
同时保存 dimensions（目标）、measuredNeutral（网格实算）、maximumTargetErrorCm（残差）和 morphWeights；超出形变范围时报告最接近结果。
四肢围度优先按垂直肢体轴线的截面测量；若使用水平截面，明确标注。

## 4. 用原商品图和裸模生成六张独立图像

默认生成六个独立高分辨率文件，使用生成器实际支持的尺寸并记录像素尺寸。
不要把一张 2×3 拼图裁成六张后称为六次独立高清生成，也不要用放大冒充原生细节。
将原商品照片作为服装细节依据，将同一版本裸模的渲染作为体形和姿态依据。
保存 human-model.json 的版本、资源指纹和 poseDegrees；所有视角复用同一体形与姿态。
先完成尺寸/姿态调节再冻结相机：Human Studio 的尺寸调节和预设会重新取景，导出的状态 JSON 不包含相机。
需要严格可比的投影或深度时，在三维渲染器另存并复用明确的相机/投影矩阵；不宣称 UI 截图天然完成相机标定。
固定人物、服装、背景、光照、相机规则及中性姿态，保持完整身体和必要边距。

| 文件 | 内容 |
| --- | --- |
| `front.png` | 正面全身，手臂稍离躯干，衣服自然垂落 |
| `side.png` | 明确 90° 的侧面全身，保留躯干厚度 |
| `back.png` | 背面全身，未观察到的结构标为推断 |
| `closeup.png` | 穿着状态下的织纹、领口、接缝和关键商品细节 |
| `pose.png` | 与选定正面图对应的人体关节点和连接线 |
| `depth.png` | 与同一正面相机和姿态对应的相对深度图 |

优先从确定的正面图执行真实姿态估计；或从三维骨架投影点线。
深度优先使用三维 Z-buffer 或实际深度估计器。使用单目模型时，保留模型名、版本和相对深度语义；
不能仅凭 Depth Anything 输出宣称得到真实厘米深度。
如果用户要 Image Gen 风格的姿态/深度图，或缺少推理工具，可生成示意图，
但标注 `illustrative`，不把其点线或颜色当成测量数据。
对来源不匹配的姿态和深度图，重新对齐或重新生成，不谎称逐像素一致。

提示词包含：原图外观约束、裸模版本和参数、视角、姿态、相机、画幅、分辨率及推断项。
若工具支持批量独立输出，一批完成；否则分次调用，仍交付六个独立文件。
跨视角优先复用同一人体、骨架和相机，减少逐张自由生成造成的体形漂移。

## 5. 拟合与 OpenCV 验证

分别评估两个问题：
1. 对原始照片的拟合：能约束多少真实可见信息？
2. 对生成视图的拟合：六张图和三维人体是否内部一致？

不要把第二类结果当成独立的真实人体测量证据。
用生成器输出拟合生成器输入裸模，属于闭环一致性检查，不是独立验证。
只用单张真实图时，侧背部体形仍依赖先验；输出这一限制。

用 OpenCV GrabCut、背景分割或可用的人体分割模型建立参考掩膜。
检查并修正把背景、阴影或肢体间空隙误填为人体的失败情况。
展示掩膜；低分辨率分割再上采样时记录其分辨率，不暗示边界具有原图像素精度。

先校准或近似对齐相机和尺度，再冻结一套对比锚点。
从实际三维网格渲染或光栅化投影掩膜；明确正交/透视假设。
初始与优化后的对比使用相同参考掩膜、评价区域、像素分辨率和相机设置。
若相机也被优化，单独记录其贡献，并另做冻结相机的对比。

计算并保存：
- IoU = 交集面积 / 并集面积。
- Dice = 2 × 交集面积 / 两个掩膜面积之和。
- 对称轮廓距离的均值及 P95，单位是评价图像像素。
- 可选躯干、四肢区域结果；裸模与穿衣人物比较时说明头发、衣物和手部差异。

生成可见叠加图：绿色为重合、粉色为参考独有、青色为模型独有。
同时提供裸模前、侧、背和透视渲染快照。
不要把 IoU 的百分数称为人体尺寸准确率，也不要把像素误差直接称为厘米测量误差。

## 6. 有约束地迭代改进

保存初始参数和指标，再优化宽度/厚度轮廓、姿态中心线、肩臂和其他可辨识参数。
使用 SciPy 或三维软件的真实优化，不靠手工修改报告里的分数。
保留合理人体比例、正尺度、连续形变和胸腰截面约束，
避免通过压扁胸部、扭曲肢体或追随发髻形状换取更高 IoU。
衣服轮廓只能提供穿衣包络；不任意减去固定松量来制造裸身围度。

有可比原始多视角时，尽量留一个视角不参与拟合，用于检查泛化。
生成的背面即便未参与优化，也只能是生成视图内部一致性检查。
每轮记录参数、损失、各视角指标、约束是否通过，并显示改进和退步。
低分辨率搜索后，用实际导出网格在最终评价分辨率重新计算指标。

目标是在约束下获得有意义的改进，而不是达到某个任意分数便宣布准确。
连续两轮改进很小、开始违反约束或不能改善最弱视角时停止，保留最佳可解释版本。
不能解决的偏差明确列出，不通过重新生成更像裸模的“参考图”来隐藏误差。
需要重新生成视图时，作为新迭代记录，旧参考仍保留。

## 7. 同步参数化查看器

查看器加载最终拟合的网格，默认滑块、尺寸显示、相机和参数文件使用同一版本。
以真实骨骼和蒙皮调节肩、肘、髋、膝及手指；关节角用度，尺寸用厘米，两组参数独立。
Human Studio 当前尺寸和角度控件步长均为 0.1；用实际界面/模型约束校验，不能把该数值当作通用平台保证。
导入时验证 version 与 asset 指纹，保留 morphWeights 和完整 poseDegrees；API setPose 会替换整张姿态表，局部修改应先合并。
更改胸腰臀时实际改变顶点；不要只更新标签，也不要依赖生成图片模拟滑块效果。
相对有偏移的截面中心缩放，避免改围度时无意移动身体中心线。
载入缓存后，按当前控件的类型、范围和步长校验并规范化参数；也可拒绝不符合控件约束的状态。
浏览器会自行钳制和取整 range 的 value，因此应以一份规范化后的状态统一建立控件、标签、网格和导出数据，
不能让控件显示已取整数值而几何仍使用缓存小数。对同版本的越界、非法类型和非步长整数倍缓存分别测试，
并更改身高后从网格截面复核围度标签，避免全局缩放使尺寸显示与实际周长脱节。
为保存状态加入模型版本或哈希，拒绝用旧版本缓存覆盖新拟合默认值。

检查：默认顶点与导出的查看器网格一致；滑块确实改变几何和画面；
相机切换有效；旧状态不污染新默认；窄屏无横向溢出；没有运行错误。
“按这些参数生成六图”按钮只提交明确包含当前参数和原图引用的新请求。
没有可调用的生成后端时说明这一点，不伪装成已自动完成生成。

## 8. 输出体形数据和证据

每个尺寸至少包含：名称、数值或 null、单位、定义、截面/标志点、来源类别和限制。
使用来源类别：`observed_scaled`、`clothed_envelope_estimate`、`prior`、`mesh_parameter`、`unavailable`。
另记 `mesh_checked` 布尔值；几何检查通过不会把先验升级为真实测量。
无法估计的胸点距、下胸围、肩斜、前后腰节长和裆弧保留 null，不用常见数值填成“实测”。
不生成没有统计依据的置信区间；给出具体误差来源和尺度敏感性。

示例记录：
```json
{
  "name": "chest_girth",
  "value": null,
  "unit": "cm",
  "definition": "horizontal torso circumference at the selected chest level",
  "basis": "unavailable",
  "mesh_checked": false,
  "limitations": ["single front view", "height unknown", "garment obscures body"]
}
```

最终交付：六个独立图片、可调节裸模及参数、真实三维快照、OpenCV 叠加证据、
优化前后指标、CSV/JSON 尺寸表和简短说明。
将可打开的证据直接展示或链接，不能只说“已验证”。
区分已执行的工具验证、人工目视检查、尚未执行的检查。
总结完成内容、最弱匹配视角、仍依赖先验的尺寸，以及下一步需要什么真实证据。

## 可复用的核验脚本

需要计算指标或测量真实网格时，阅读 [工具与证据实现](references/tools-and-evidence.md)。
使用 `scripts/verify_masks.py` 输出 OpenCV 指标和叠加图；
使用 `scripts/measure_mesh.py` 测量已导出网格的指定连通截面。
使用 `scripts/inspect_human_state.py` 检查 Human Studio 状态合同；提供对应 human.json 资源后可独立重建并核验中性姿态尺寸。
状态检查不替代真实浏览器关节变形、已导出 OBJ/GLB 的单位与蒙皮验证；完整检查命令见 Human Studio 参考。
这些脚本不替代原图获取、生成服务、人体拟合或解剖标志点判断。

## 完成前检查

- 原始商品图已实际获取和查看，来源可追踪。
- 六张独立图片存在，尺寸记录真实，商品细节保持一致。
- 推断背面、示意姿态、相对深度和已执行的估计器来源均有标记。
- 三维快照来自实际网格；尺寸来自网格截面或明确标注的其他依据。
- 初始/最终指标来自同一评价协议；分割失败已经检查。
- 优化带来的改进、退步和不可辨识项都保留。
- 查看器几何、厘米尺寸、关节姿态、保存状态及模型版本/资源指纹同步。
- 目标尺寸与网格实算尺寸分别保留；确认 OBJ 厘米、GLB 米以及正确坐标轴。
- 保存/重载/导入恢复实际形状与姿态，PNG 来自真实三维渲染；历史简化模型评测未冒充当前解剖模型验证。
- 对生成视图的匹配未被包装成真实人体尺寸验证。
