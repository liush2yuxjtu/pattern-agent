使用指南

整个实验从 统一README入口 查找；在线案例库 默认展示五个真实案例，可搜索设计意图、筛选缝合状态、切换二维/三维、打开完整规格并下载文件。“实验说明”由同一README生成，集中连接输入、代码、产物及证据。

这个项目交付什么

这是一页原型与改版结果的对照工具。左侧固定展示原型，右侧展示一个已经运行、生成文件并经过独立审计的改版案例。

这里的“一维规格”指可阅读、保存和审阅差异的文本规格。中文 YAML 同时保存完整二维坐标和语义，并不是只有尺码表的一串参数。

原型输入 意图与输出
完整中文输入 YAML 本案例实际输入的设计意图
原始二维 DXF 与纸样图 新 YAML、规格差异与 DXF 坐标补丁
从原始 DXF 重建的三维示意 新 DXF、新二维图及对应三维示意

在线演示：https://liush2yuxjtu.github.io/pattern-agent/intent-edit-review/。

需要检查真实物理记录时，打开独立的 物理实验台（发布路径 /intent-edit-review/physics/）。它另含完整中文 YAML、当前二维 SVG、设计意图、原始文件下载及实际三维回放；旧对照页仍保留原有功能。

两条工作流程

建立原型包： 原型 DXF → 读取实体、曲线和文字 → 完整中文 YAML → 二维重建与互校 → 来源绑定的三维示意 → 保存原型包。

使用原型包改版： 原型 YAML + 原型 DXF + 设计意图 → 明确目标与不变区域 → 新 YAML 和规格补丁 → DXF 坐标补丁和新 DXF → 独立互校 → 新二维与三维对照。

当前网页负责展示这些已生成的文件。生成代码位于同一仓库的 experiments/intent-edit-benchmark/；网页选择器不调用模型或远程生成服务。

三分钟上手

  1. 打开演示，在顶部选择一个已验证案例。
  2. 阅读右栏的实际设计意图。左栏的原型文件不变，两侧摘要显示当前案例相关的量测项目。
  3. 对照二维纸样。右侧灰色为原型叠加，绿色为本案例输出；点击图形可以放大。
  4. 拖动任意三维视图，两侧相机会同步变化。滚轮缩放，方向键旋转；正面、背面和复位按钮也作用于两侧。
  5. 打开“查看完整YAML”阅读全文；摘要只是索引，不能代替完整规格。
  6. 点击“查看差异”阅读修改前、修改后和差值，再切换“规格补丁”或“DXF补丁”查看完整原文。
  7. 保存需要的 YAML、DXF 和补丁。下载直接使用内嵌原始字节，不通过图片或浏览器截图反推纸样。

物理实验台怎么用

  1. 选择原型或袖口加宽案例，先看顶部整衣结论。本轮两个案例各61/61帧离散数值验收 PASS；结论针对记录中的实际来源、条件和保存状态，不代表面料实测或真人合身通过。
  2. 点击“二维纸样”查看本款完整 SVG。拖动平移，用加减按钮、滚轮或双指缩放，用“复位纸样”回到全图。
  3. 点击“完整规格 YAML”阅读实际中文全文。弹层可滚动、回到顶部；按 Escape 或关闭返回原入口。下载 YAML 与 DXF 得到真实源文件字节。
  4. 展开“本款设计意图与变化”。袖口案例还可下载 spec-diff.json 与 geometry-patch.json；独立 intent.txt 可从中心 README 的案例结果目录取得。
  5. 切回“三维物理”，拖动时间轴检查真实保存状态。正常记录为初始状态加60步，共61帧；seek 只读保存数组，不重新计算。可切换布料、应变、应力、折角、接触和接缝六种显示，选择15条缝，点击真实面片查看二维材料三角形和数值。
  6. 保存记录 JSON、当前网格 OBJ 或完整 HTML，再核对本款报告与文件摘要。失败研究轨迹保持 FAIL；三维外观和下载成功都不能覆盖独立几何结果。

原型与袖口加宽有当前支持的来源配置。其余袖长、衣长、前领三个输入仍为 BLOCKED：PROFILE_REQUIRED，不会继承原型的物理结果。

如何阅读和交接规格

设计人员先看款式特征、目标尺寸、结构决定和本次差异，再核对明确保持的区域。纸样设计人员继续检查完整几何、接口、定位点及线条用途。裁剪与缝制人员应重点看裁数、净裁角色、缝级、折边和待确认项。

“待确认”不是默认批准值。几何可以从 YAML 重建，并不代表材料、净裁角色、实际装袖前后、缝制工艺和生产尺码已全部批准。

保存单文件与离线使用

演示主文件是 web/intent-edit-review/index.html，约 5.9 MB。完整 YAML、DXF、补丁、二维 SVG、五套三维模型、CSS 和 JavaScript 全部内嵌。保存原始 HTML 即可携带，不需要旁边的模型、字体或脚本文件。

独立 Chrome 已在禁用网络的 context 中直接打开仅含这一份 HTML 的目录，验证四案例、旋转、完整 YAML 和 DXF 保存。某些受管浏览器会禁止 file://；本机遇到的策略限制单独保留，不能靠关闭安全策略来解决。

本在线文档页是独立辅助页面，不是演示 HTML 的运行依赖。

物理实验台另有“保存完整 HTML”：保存实际轨迹、原始规格与二维图后，可用同一份文件阅读和回放。它与约5.9MB的静态对照演示是不同产物，不能互换来源或验收记录。离线字节验证与环境是否允许原生 file:// 打开分别记录。

目前的三维含义

原对照页的三维是从每一版自己的真实 DXF 生成的静态几何装配示意。它可以帮助理解袖长、衣长、袖口、领口等修改如何影响空间外观。

独立物理页显示真实求解器保存的状态与独立报告。本轮原型及袖口两个案例各61帧离散数值验收通过；原型全程最大主应变185.61%，袖口138.88%，不能据此认定面料耐受、舒适或合身。此前失败保留。图形单位 U 尚未标定；物理试验明确假定1U=1mm，不能据此批准实际比例。材料标定、生产批准和真人试穿仍为 NOT_RUN。

单文件构建过程

build.py 读取基准和四个输出的实际 DXF、中文 YAML、规格差异和坐标补丁。它校验规格结构、DXF 实体与规格几何的对应关系，并核对每个模型的来源摘要。

构建器将完整文件编码为 base64，把实际二维图元和 SVG 与对应模型一起写入唯一的 app-data JSON。最后把样式、视图绘制代码和交互代码内联到 HTML。

浏览器启动时读取内嵌数据，检查文件长度，在支持的安全上下文中检查 SHA-256，并核对模型与当前 DXF/YAML 的版次。它不通过 fetch 拉取模型，也不从 CDN 导入三维库。

独立物理项目怎样连接

物理代码和发布路径均位于 physics/ 子目录，不替换对照演示或静态缝合结果。详细实现见 物理实验说明。

阶段 实际职责
prepare_experiment.py / verify_source_mesh.py 读取实际 DXF/YAML、材料坐标、支持配置、15条缝及真实人体，另行核对来源、CAD/UV和拓扑
run_native.mjs 运行本次冻结并编译的 WASM 核心和接触组件；保存准备状态与独立几何门，失败保留原因
derive_folds.mjs / audit_experiment.py 从真实保存坐标派生折角，并独立复算每帧几何、张量、折角和时钟
verify_resume.py 新建进程从保存状态继续，核对实际下一步；与界面的只读 seek 分开
build_viewer.py / recording-codec.mjs 校验输入、记录和报告摘要，进行无损记录编码，把实际文件、二维图、脚本和轨迹内嵌到单份 HTML
verify_viewer.py 在真实浏览器检查原文/原字节、全部帧、颜色属性、面片、接缝、导出重开与窄屏；收据绑定本次代码和数据
verify_gpu_buffers.py 观察真实WebGL2绘制，从当前颜色属性VBO读回数据；不以CPU属性数组代替缓冲区读回
verify_svg_fallback.py 强制禁用WebGL，核对同一网格的软件三维、完整保存状态、二维及规格功能

构建器从已验收对照数据读取 source_package：完整 files、实际 twoD、自然语言 intent 与 changes。文件逐一与仓库原始字节核对，二维来源与物理输入的 DXF/YAML 摘要一致，不能把旧模型换个标签套到新输出。

物理输入另存本次条件副本和实际可执行文件摘要；更改默认参数不会改写历史实验。本轮原型和袖口各61/61帧离散数值验收 PASS，另外三个案例仍为 BLOCKED：PROFILE_REQUIRED。正式候选轨迹不能绕过初始几何门；历史失败研究记录也不改判。通过范围限于实际保存状态与估计材料模型，材料耐受及真人合身不在本轮通过范围内。

为什么三维没有沿用旧模型

五个 *.mesh.json 分别对应基准和四个改版。每个模型保存实际二维边界顶点到局部 UV 的绑定、三角形、三维位置、法向和明确的构造信息。

衣身使用实际轮廓边界的静态映射及内部调和插值。袖片使用来源绑定的纵向参数和截面映射。领条采用明确声明的展示折叠，沿对应版次的领圈摆放。详细公式、近重复端点的处理和假设见 geometry/README.md。

同一展示姿态用于全部案例，未改裁片的数据保持相同。所有模型共用一套包围框和相机参照，不按每个案例分别自动缩放，从而避免把真实长度变化抵消掉。

这些映射不是等距布料展开或批准的缝制方法。三维位置的来源可以核对，物理合理性仍属于另一个验收边界。

浏览器绘制与状态

静态对照的 viewer.js 直接把模型三角形送入 WebGL；WebGL 不可用时，使用同一套三角形进行 CPU 投影和 Canvas2D 绘制，不替换成固定图片。

两侧共享相机的 yaw、pitch 和 zoom。选择案例只更换右侧的实际输出模型、二维图、文件和相关摘要；左侧完整输入文件始终相同。

完整 YAML 和补丁通过文本节点显示。保存文件时从原始 base64 恢复字节，生成 Blob 下载。页面不把浏览器内重新序列化的对象当作原始 DXF 文件。

物理页的 physics/viewer.mjs 使用自己的完整画布切换：二维显示真实 SVG，三维显示实际轨迹与场。优先使用WebGL；浏览器未提供WebGL2时，使用同一套scene、camera、全部网格及保存状态作SVG软件投影，不替换成静态图片。软件路径只在视角、帧、模式、可见对象等变化时重画，并标示“CPU三维”。完整中文 YAML、二维图与原文件下载不依赖WebGL。回放读取保存数组，切帧不会积分或修改源文件。

哪些文件应该重新生成

  • 只改视觉或文案：重建单文件演示，并复测受影响交互和显示。
  • 改 DXF 或规格：先重新运行对应编辑器和独立互校，再重建相关模型、演示和全部来源验证。
  • 只改文档：运行文档构建和文档浏览器验证；确认演示 HTML 的摘要未变。
  • 只改中心 README 或导航：重建 docs/hub 并验证目录、真实页面往返及旧 comparison/sewn 文件摘要；不必重建旧模型。
  • 修改三维构造公式：重建五套模型，重新检查几何响应、未改片、实际 UV 和故障控制，再验证浏览器像素。
  • 修改物理求解、接触或条件：使用新运行目录冻结源码、重新计算和独立验收；修改物理界面则重建物理 HTML 并更新匹配代码/数据的浏览器收据。

不要直接手改发布 HTML 中的 base64、SVG 或模型摘要来跳过这些步骤。

完整中文 YAML

YAML 包含文件约定、款式特征、关键尺寸、结构和接口、线条用途、缝级观察和完整二维几何。完整几何保存点位、线型、文字及排版关系，不要求再读取原设计照片才能重建二维图。

基准共有四块纸样、204条曲线/直线、27条文字和1487个多段线顶点。量测和工艺解释与精确点位并存：人可以先读款式和尺寸，纸样人员可以继续检查几何，程序也可以独立验证文件是否一致。

网页中几行“YAML 摘要”只是入口。完整下载和完整阅读弹窗均对应实际规格全文，不能用摘要截图代替完整文件。

规格补丁

spec-diff.json 使用 guarded-semantic-spec-patch/1。顶层包含基准摘要、目标摘要和操作数组；一项替换操作包含 op、path、old 与 value。

{
  "op": "replace",
  "path": "/文件约定/纸样版本",
  "old": "基准版，当前没有改款",
  "value": "基准版改为基准测试 01_sleeve_length"
}

路径不是猜测自然语言含义的指令。应用补丁前应核对基准摘要和旧值，防止把本次变更误套到另一个款或另一个版本。

DXF 坐标补丁

geometry-patch.json 使用 guarded-dxf-coordinate-patch/1。它保存基准/目标摘要及受保护的坐标修改。操作记录定位原始组码对位置，保留原值和新值，同时带上可阅读的裁片、线名和实体顺序。

{
  "pair_index": 3154,
  "code": 20,
  "old": "-1981.965485",
  "value": "-2001.965485",
  "裁片": "袖片",
  "线名": "袖片袖口横线第1段",
  "实体顺序": 129
}

这是实际袖长案例中的一条记录。补丁依赖精确基准，不能跨 DXF 重新导出、重排实体或修改编码后盲目重放。工具会检查摘要和旧值，而不是仅凭线名覆盖坐标。

三维文件与内嵌索引

五套模型的格式为 source-bound-static-assembly/1，单位为 U，模式为 static_geometric_assembly。它们包含来源 DXF/YAML 摘要、共同姿态、包围框、面片以及边界来源绑定。

演示的唯一内嵌数据块为 app-data，格式为 intent-edit-review/1：

  • baseline 保存基准，cases 保存四个输出。
  • files 保存文件名、仓库路径、MIME、原始字节长度、SHA-256 和 base64。
  • twoD 保存实际图元、SVG 及来源摘要。
  • threeD 保存模型原始 JSON 字节、模型摘要及来源摘要。
  • 案例另外保存实际意图、可阅读摘要和修改前后量测。

摘要标签正确不代表文件正确。验证必须检查实际坐标、图元和网格，不能只检查 source_sha256 一类字段。

物理记录和完整来源包

独立物理页使用 intent-physics-review/1，与静态对照的 intent-edit-review/1 分开。每个实际案例包含本次 input、无损编码的 recording、独立 audit、完整中文 conditions 和 source_package。

数据 需要核对什么
source_package.files 实际 YAML、DXF及本案例存在的规格 diff/几何 patch；文件名、MIME、字节长度、SHA-256和base64原始字节
source_package.twoD 完整 SVG、二维图元与源文件摘要；原型204条线、27处文字，不能用轮廓截图代替
source_package.intent / changes 实际自然语言意图、修改前后说明；原型明确标注尚未应用新意图
input.json 该次条件副本、实际材料坐标与三角面、15条缝的全部位置别名、真实人体、DXF/YAML来源与求解器身份
trajectory.json 实际坐标、上一时刻坐标、场、接触与时钟；正常记录61帧，不把准备迭代当成物理时间
preparation-gate.json / audit.json 穿着准备与完整轨迹的独立结论，绑定实际输入和记录摘要
resume-independent.json 新进程恢复后的下一步检查，不能用网页时间轴成功替代
viewer_sources / 界面收据 本次查看器代码与实际案例输入/记录的绑定；旧程序或其他案例的 PASS 不自动套用

原型可下载完整输入 YAML/DXF；袖口案例可下载新 YAML、输出 DXF及两份实际补丁。设计意图在页内完整显示，独立 intent.txt 保存在案例结果目录。记录 JSON、当前帧 OBJ 和完整 HTML 是物理页的其他导出，不能将 OBJ 当作新版 CAD 源文件。

二维 U 尚未标定。1U=1mm只属于明确记录的本次数值假设；应力实际计算单位为Pa、界面以kPa显示，应变以百分比显示，折角以度显示。估计材料参数、标准人体与照片成分不构成实测力学或真人合身证明。

四层独立验证

  1. 文件层： 实际下载、内嵌原始字节和仓库源文件逐字节一致。
  2. 二维层： 从实际 DXF 读取实体、顶点和文字，与完整 YAML 和实际 SVG 互校，重算尺寸、接口和保持区域。
  3. 补丁层： 检查基准摘要及旧值，正向重放，再逆向恢复；非法、缺失或不确定意图不能生成伪成功产物。
  4. 三维与浏览器层： 检查实际边界 UV、拓扑、构造公式、内部点、改未改片；用真实指针和键盘验证图像、下载和响应式布局。

独立内嵌审计器不导入生成器。现有八项自身测试与六项实际 HTML 故障控制覆盖了旧 SVG、来源全被伪造的旧模型、重算摘要后的三维坐标篡改、截断规格及缺案例等情况。

物理另加独立检查链：先核对 CAD/UV/来源，再从准备结束时的真实float32坐标检查人体与自交；对全部保存帧独立重算接缝、拓扑、人体穿入、双方边面穿越、严格三角面穿插、张量和折角。人体不入顶点不代表整个面片不穿体，采样几帧也不等于完整轨迹通过。恢复检查和实际浏览器验收各有独立报告。

验收结论的边界

PASS 必须带对象：文件互校、补丁或浏览器通过，不等于生产、缝合或合身通过。未标定的“加长2厘米”、缺条件的“抬手更舒服”、负值袖口等请求分别应阻止或拒绝。

保留原型已有微小轮廓间隙和待确认工艺，不把本次坐标编辑冒称完整生产净样修复。物理布料与真实试穿需要另外的输入、求解和验收证据。

本轮原型及袖口两个案例各61/61帧离散数值验收 PASS，另外三例仍为 BLOCKED：PROFILE_REQUIRED。两案例的全程最大接缝间隙、离散人体穿入、双向边面穿越及严格自交均为0，张量、折角和数值穿袖检查逐帧通过。来源各含15条缝、4个预期开口；两份实际二进制各10组机制对照通过，从0/30/59帧在新进程继续时，坐标、上一坐标、场、接触、步数和时间六项逐字节一致。

原型全程最大主应变为185.61%（第29帧，末帧139.51%），袖口为138.88%（第60帧）。这是估计材料模型的数值结果，不能推断面料耐受、舒适或真人合身。七项机制/界面检查仍只在自己的证据边界判定；缺少本次证据的项目保留 NOT_RUN。材料标定、真人试穿及生产批准没有因离散数值 PASS 而获得批准，原有严格门槛和历史失败继续保留。

常见问题

页面打开了，但三维空白。 等待文件校验完成，查看页面错误提示和浏览器控制台。模型来源不匹配时应修复输入配对并重建，不删除校验。独立物理页优先WebGL，禁用时用同网格SVG软件投影，仍可旋转、切帧、查看字段；二维纸样与全文YAML照常使用。不能用旧模型或静态截图替换失败结果，也不需要更改浏览器安全设置。

修改了 YAML，却还是旧图。 先生成并互校对应 DXF，再重建当前模型和 HTML。只改摘要或标签不会生成新纸样。

要输入一个新的自然语言设计。 当前选择器只显示四个已实现案例。先将新意图规范为可量测目标、单位、保持区域和联动约束，再实现或审核对应编辑代码，生成全套产物并独立核验，最后加入展示清单。

几何通过，是否可以发给工厂直接生产？ 仍需要批准单位标定、材料、裁数、净裁角色、缝制与折边等；几何示意没有完成物理试穿验收。

上线后看到旧页面。 核对具体部署提交和返回 HTML 的摘要。发布工作流成功、缓存或旧截图均不能证明浏览器正在运行新产物。

演示和本文档分别为独立 HTML。三维是来源可追溯的静态几何示意；U 未标定，生产和试穿仍需另行确认。
