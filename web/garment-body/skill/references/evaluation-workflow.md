# 反馈与功能评测迭代

本流程采用 Anthropic skill-creator 的实际执行、证据评分、评测自身批评、人工查看和反馈迭代。
先读项目固定的 `tools/skill_evals/upstream/SKILL.md` 与 `agents/grader.md`；不要只套用成绩表样式。

## 先确定本轮改什么

保存用户反馈、旧技能、旧输出和原始评分，给新执行单独目录。区分技能指令改进、模型参数
调优、评分器修正及查看器改进；其中任何一种的成功不能自动证明其他几种成功。
已有用户选定的原图、Image Gen 引导和尺寸授权应复用。只改评阅流程时，不重新付费生成或
无意义重跑未变的求解器。改变了技能执行行为，则用相同输入重新执行相关功能任务，保留旧版
对照与失败；实际原生 Claude 路由未运行就标 BLOCKED，不用显式提供技能的执行冒充触发评测。

## 检验输出，也检验断言

断言应验证用户想要的结果，而非只有文件名、控件数量或工具调用成功。对本任务分别核验：

- 原图与商品细节是否保留，六类生成输出是否实际生成且独立；复用和未运行项分开标注。
- 实际厘米校准、骨骼和所有视图是否来自同一个保存状态。
- 原图肩臂、躯干、腰臀与可见手腕是否对齐，是否仍有方向明显相反的前臂。
- 真实侧背中的掌背朝向、屈指、双手空间关系和穿身是否符合目标动作。
- 尺寸数据是否仅为先验/条件人体，原始图像能否支持所声称的真人测量准确性。

评分保存 `expectations: [{text, passed, evidence}]`，附带 `claims` 和 `eval_feedback`，引用
实际原始文件及数值。UNKNOWN 不计为通过；描述性的通过数量不覆盖关键失败的 overall 结论。
检查断言会不会让明显错误的输出通过。例如：把模型缩进衣服轮廓、只对齐脸和手腕、让双手
在深度上分离、用零覆盖射线宣称无碰撞、给侧面偷偷换姿态。负例应证明对应局部门槛能识别
该错误，不能仅依赖该候选本来就在另一区域失败。新增门槛另记版本和来源，勿倒填为预先冻结。

## 把实际结果交给人看

通用配对执行使用固定的官方 `eval-viewer/generate_review.py`，后续轮次带
`--previous-workspace`，保留 Outputs、Benchmark 与反馈。图像证据作为每个案例 Output 中的图库，不能以自定义仪表盘替换官方外壳，也不把官方查看器
藏进历史折叠区。需要复杂叠加控件时提供独立的 details.html，并从 Output 链接过去。

当前 `eval.html` 使用固定官方模板，Output 展示原图、引导、实际投影及前后叠加，Formal Grades
展示实际断言和证据，Feedback / Submit All Reviews 采用官方流程。基线与候选的描述性断言
比较不称为新旧技能实验；历史六次执行另存 history.html，原始分数不混合。人体尺寸和动作
编辑入口载入当前案例的同一状态。

官方反馈键绑定本轮包含源指纹的实际输出；基线与候选按 run_id 分别保存，两个 URL 共享
同源草稿。Submit All Reviews 导出官方 `reviews[{run_id,feedback,timestamp}]` 与 `status`。
旧自定义表仅在本轮没有官方草稿、且原图/state/mesh/camera 指纹全部相同时恢复文本及显式判断，不覆盖新的
官方反馈，也不改自动评分。自动化测试文本不是人工验收；仅本地保存与下载，不自动外发。

## 下一轮与停止条件

读实际反馈及执行轨迹，从失败中提炼可复用原因，保持正文精简，把案例坐标与阈值留在案例
协议中。优先修最影响动作的失配，保存各区域进退，避免为消除穿腹反而把肘拖到腕下。
修改后重跑受影响的功能与反例、重建评阅页和技能包，再实际验证图库、反馈持久化/导出及
模型导入。到达平台期时交付最佳可解释候选和剩余 FAIL，等待用户查看；不要改分数冒充匹配。

可执行入口与来源见 [工具与证据](tools-and-evidence.md)。运行次数、token 或时长缺失就留空；
只有实际配对实验才报告其比较，只有独立原图和尺度支持时才讨论真人尺寸误差。
